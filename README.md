# 小说创作助手

> 一句话灵感 → 设定档案 + 12 章大纲 → 一章一章往下写，越写越记得住。

一个跑在**自己电脑上**的中文长篇小说创作工具。给它一句话灵感，它会先生成**设定档案**（世界观、人物、伏笔、线索、时间线）和 **12 章大纲**，然后逐章写作；每写完一章自动把「这一章发生了什么」写回记忆库，下一章接着写，前后不打架。

界面全中文，浏览器打开就能用。

---

## 特性

| 能力 | 说明 |
|---|---|
| **设定档案** | 一句话灵感 → 前提、世界规则、人物、伏笔、支线、时间线 |
| **12 章大纲** | 逐章目标 + beats，写作时按大纲推进；界面「设定」标签页随时可看，也能单独导出 |
| **四层记忆库** | 章级摘要 → 人物状态 → 关系变化 → 时间线，逐层回灌给下一章 |
| **一致性校验** | 写完自动比对前文设定，抓出人物/时间/设定冲突 |
| **AI 痕迹检测** | 从用词、句式、段落节奏三个维度打分；超阈值自动重写降味 |
| **钩子与伏笔** | 自动回收已了结的伏笔，记录新埋的钩子，避免烂尾 |
| **关系图谱** | 人物关系随章节演化，可视化查看 |
| **长文不截断** | 被模型截断时自动接着往下写，直到本章写完 |
| **多身份隔离** | 每个人只看到自己目录下的作品，服务端不落盘身份码 |
| **四种导出** | 大纲 / 全文 / 设定档案 / 质量报告，随时留底 |

## 快速开始

需要 **Node.js 18+**（推荐 20 LTS）。

```bash
npm install
npm start
```

然后在浏览器打开 <http://localhost:3000>。

> **随包附了一份演示作品《褪色名录》**（12 章大纲 + 已写 2 章 + 完整记忆库）。
> 首次启动会自动把它认领为「本机所有者」的作品，打开就能看到「写到一半的作品长什么样」。
> 不想启动程序的话，可以直接看 [`演示作品-大纲.md`](./演示作品-大纲.md)，了解本工具排大纲的颗粒度。
>
> 注：首次启动会把 `data/novel.json` **移动**进 `data/users/<身份码>/`，所以它在 git 工作区里
> 会显示为已删除。想还原演示文件，`git checkout -- data/novel.json` 即可（不影响已认领的作品）。

改代码时的开发模式（前后端热更新）：

```bash
npm run dev
```

## 配置模型（必做）

本工具**不自带模型**，要用你自己的大模型 API。第一次打开会强制要求配置，配好才能用。

推荐 **DeepSeek**：便宜、中文小说语感好，写十几章大约几毛钱。

1. 到 <https://platform.deepseek.com/api_keys> 注册并创建一个 API Key（形如 `sk-xxxxxxxx`）
2. 回到页面填写：

   | 字段 | 填什么 |
   |---|---|
   | 接口地址 | `https://api.deepseek.com/v1` |
   | API Key | 刚复制的那串 |
   | 模型 | 点右侧「拉取列表」，会列出你这个 Key 下**真实可用**的模型，选一个 |

3. 点「测试」，通过后保存。

**任何 OpenAI 兼容接口都行**——Kimi、智谱、通义，以及各类中转站，只要有 `https://.../v1` 地址和一个 Key。

> 模型名以接口返回为准，不以预设为准：预设里的名字只是方便点一下，
> 填完 Key 会自动拉一次真实列表，也可以手填任意模型名。

## 怎么用

1. **建书**：首页写一句灵感（例如「一个档案员发现自己的记忆被人系统性抹掉」），点生成。
   等 1–3 分钟，得到一份设定档案 + 12 章大纲。
2. **写下一章**：点「写下一章」，模型依据大纲、前文、记忆库生成正文；被截断会自动续写。
3. **自动收尾**：每章写完自动做三件事——
   - **质检**：扫 AI 味，分高则自动重写降味；
   - **回收**：标记已了结的伏笔，记录新埋的钩子；
   - **记忆**：把本章的人物关系变化、时间线推进写进记忆库。
4. **随时看设定和大纲**：写作台「设定」标签页。
5. **随时导出**：写作界面 →「高级设置」→「导出」（大纲 / 全文 / 设定档案 / 质量报告）。

## 目录结构

```
├── src/                    前端源码（React + TypeScript）
│   ├── components/         界面组件（配置向导、写作台、设置页…）
│   ├── hooks/              数据钩子
│   └── lib/api.ts          统一 API 客户端（含 SSE 流式读取与超时看门狗）
├── server/                 后端源码（Express + TypeScript）
│   ├── index.ts            服务入口、鉴权、路由挂载、静态托管
│   ├── users.ts            身份与数据隔离、老数据迁移
│   ├── llm.ts              模型接入层（OpenAI 兼容 / 本机 CodeBuddy）
│   ├── novel.ts            建书、续写、回收、校验、导出
│   ├── aidetect.ts         AI 痕迹检测
│   └── engine/             写作引擎（记忆四层、钩子压力、一致性校验、文风）
├── web/                    前端构建产物（已构建好，Express 直接托管）
├── data/                   运行时数据（含演示作品《褪色名录》）
├── .env.example            环境变量示例
└── package.json
```

> `web/` 是构建产物但**必须随仓库提交**：`npm start` 只编译后端，前端由 Express 直接托管，
> 不会自动构建。改完前端要跑 `npm run build` 再重启。

## 数据与隐私

- 作品存在本机 `data/users/<身份码>/`：`novel.json`（设定、大纲、正文、记忆库）、`chat.db`（对话记录）。
- **身份码**由浏览器首次打开时用 `crypto.getRandomValues` 生成，存在浏览器本地；
  服务端只保存它的 `sha256` 前 32 位当作目录名，**从不落盘身份码本身**，也无法反推。
- API Key 只存在浏览器 localStorage，随请求发给本地后端，后端直接转发给模型厂商，
  **不写数据库、不写日志、不落盘**。

> ⚠️ 身份码只存在浏览器里。清空浏览器数据（或换浏览器、换电脑）就找不回作品了。
> 养成习惯：写完几章就「导出 → 全文」存一份到别处。

## 常见问题

**打开提示「请先配置模型」** —— 正常，这是第一道门，按上面配置好并测试通过即可。

**点了生成一直转圈** —— 先看终端报错；多数是模型配置不对，回「设置」点一次「测试」；再确认 Key 有余额。

**端口被占用** —— 默认 3000，可换：

```bash
# Windows (cmd)
set PORT=3001 && npm start

# macOS / Linux
PORT=3001 npm start
```

**`npm install` 卡在 `better-sqlite3`** —— 该包需要编译或下载预编译二进制。确认 Node ≥ 18；
删掉 `node_modules` 与 `package-lock.json` 重装；Windows 若提示缺编译工具，装
[Visual Studio Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)（勾选「使用 C++ 的桌面开发」）；
国内网络可先 `npm config set registry https://registry.npmmirror.com`。

**「本机 CodeBuddy 登录」总失败** —— 这是给「本机装了 CodeBuddy 且已登录」的人用的可选方式，
依赖一个固定端口，容易被别的程序占用，会时好时坏。**建议直接用 API Key 方式**，稳定得多。

更多细节见 [`使用说明.md`](./使用说明.md)。
